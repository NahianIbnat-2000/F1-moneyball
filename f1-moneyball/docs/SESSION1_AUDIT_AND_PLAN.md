## Phase 1 plan (this session)

1. **Dataset registry + `dataset_status.json`** generated by the pipeline. Every dataset the site expects is declared once in `config/datasets.yaml` with what it will contain, why it may be unavailable and what is needed. Status values: published, not_yet_collected, under_validation, insufficient_coverage, unavailable_at_source, not_comparable.
2. **Richer metadata**: per-column source, transformation, missing-value treatment, limitations; per-dataset missingness, variable count, version hash, last updated, validation status.
3. **Financial provenance**: add `document_title`, `transformation`, `comparability_warning` to the schema and validator.
4. **Frontend reads statuses** from `dataset_status.json` only. Article status is derived from the statuses of the datasets it needs.
5. **Homepage** rebuilt to the brief, with a research-status block generated from metadata.
6. **Article template** with components named in the brief and its own URL per article (`/research/:slug`).
7. **Data Explorer**: dataset profile, missingness, full dictionary, classification legend, provenance panel for financial rows.
8. **Navigation** reduced to six items.

Out of scope this session (later phases): Plotly lazy loading and bundle analysis, chart download PNG/SVG, prerendering for SEO, citation file, changelog.

## Session 1 report

**Changed (pipeline)**
- `config/datasets.yaml`: registry of 7 datasets with what each will contain, why it is unavailable and what is needed.
- `publishing/status.py` writes `website/public/data/dataset_status.json` (status, coverage, observations, variables, per-column missingness, content version, last_updated that changes only when content changes, validation status and warnings).
- Data dictionary now carries source, transformation, missing-value treatment per column and limitations per dataset. Added `race_result` dictionary; `race_result` is now published when built.
- Financial schema: `document_title`, `transformation`, `comparability_warning`. Validator requires the first two for any figure and the warning for any estimate.
- Tests: 31 → 36 (registry consistency, status rules, coverage rule, version stability, every built column documented).

**Changed (website)**
- Homepage rebuilt to the brief; research-status block reads only `dataset_status.json` and `manifest.json`.
- Article template with 14 fixed sections and components `ResearchArticle`, `ArticleHeader`, `ArticleMetadata`, `TableOfContents`, `ResearchQuestion`, `HypothesisPanel`, `MethodologyPanel`, `ResultsPanel`, `LimitationsPanel`, `ReferencesList`, plus `DataAvailability`. Three articles at `/research/:slug`. Article data readiness derived from dataset statuses; no hardcoded status remains.
- `DatasetStatusPanel` replaces every page-specific "awaiting data" note.
- `ChartFrame` now shows chart ID, coverage, observations, dataset version, CSV download and methodology link.
- Data Explorer: all datasets listed with status, dataset profile, limitations, validation warnings, full dictionary with missingness, financial classification legend, row-level provenance panel for financial figures, filtered CSV download.
- Navigation reduced to six items.

**Tests run**

- Layout: 14 routes × 3 widths (1280, 820, 390): no horizontal overflow (two overflow bugs found and fixed).
- Keyboard: skip link is first tab stop, then brand and navigation in order.
